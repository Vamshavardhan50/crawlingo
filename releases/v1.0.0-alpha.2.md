# Crawlingo 1.0.0-alpha.2 — dataset generation preview

**Draft release notes. This version has not been published.** Remove this draft
notice only after the artifact matrix and registry installation checks pass.

## Dataset workflow

- Generate validated datasets from a URL file through Rust, Python, Node.js or CLI.
- Extract multiple records per page with an explicit row container.
- Validate fields, report rejected rows and failures, and remove exact duplicates.
- Write JSONL or CSV shards with local checkpoints, cancellation and resume.
- Keep bulk records in the Rust pipeline; SDK calls return a compact report.

## Efficiency and correctness

- Share immutable configuration and pending deduplication buffers across workers.
- Write JSONL directly to buffered output and avoid unused dedup work.
- Retain bounded processing, exact hash-collision checks and ordered checkpoints.
- No new speedup claim is made for these allocation changes.

## Developer experience

- New dataset-first README, runnable product fixture, API and deployment guides.
- Copyable Python/Node/Rust examples and a redesigned documentation site (deployed separately).
- Release artifacts, SHA-256 checksums and a machine-readable artifact manifest.
- Consistent version checks, prerelease validation and a shared artifact gate.

## Installation after publication

```sh
npm install crawlingo@1.0.0-alpha.2
python -m pip install 'crawlingo==1.0.0a2'
cargo add crawlingo@1.0.0-alpha.2
```

These commands are for the future published version. Until then, build the source.
Node requires 22+; Python source supports 3.8–3.13. List the actual successful
wheel/native platform matrix here after the release run; do not substitute intended
targets for verified artifacts.

## Limits

Alpha software. DatasetJob supports JSONL/CSV string-valued records and exact
deduplication. Browser rendering, heuristic selector recovery and collected Parquet
belong to separate APIs; checkpointed Parquet and distributed jobs are not shipped.

The earlier million-page/million-record run used small local HTTP fixtures on
Windows. It is not an arbitrary-site performance guarantee. Read `SCALE_RESULTS.md`
and `MIGRATION.md` before adopting the release.
